# Voicebox Project and API Integration Guide

This document explains the Voicebox project idea, how the backend works, all major API endpoints, and exactly how another project can send text and receive a voice recording.

## 1) Project Idea (What Voicebox Does)

Voicebox is a local-first voice generation platform:

- Create and manage voice profiles (cloned, preset, or designed voices)
- Generate speech from text
- Save generated audio/history
- Fetch generated `.wav` files through API
- Optionally transcribe audio, manage effects, stories, channels, and model lifecycle

Primary use case for external apps:

1. Your app sends text + profile ID to Voicebox
2. Voicebox generates speech asynchronously
3. Your app checks generation status
4. Your app downloads the `.wav` recording

## 2) Run the Backend

From repository root:

```bash
python -m backend.main --host 127.0.0.1 --port 8000
```

Useful URLs:

- API docs (Swagger): `http://127.0.0.1:8000/docs`
- Health check: `http://127.0.0.1:8000/health`

By default, data is stored under `data/` (profiles, generations, db, cache).

## 3) Core Integration Flow (Text -> Voice Recording)

### Step A: Check server health

```bash
curl http://127.0.0.1:8000/health
```

### Step B: Create a profile (or use an existing one)

Create:

```bash
curl -X POST http://127.0.0.1:8000/profiles \
  -H "Content-Type: application/json" \
  -d '{
    "name": "My Voice",
    "description": "Profile for app integration",
    "language": "en",
    "voice_type": "cloned"
  }'
```

List profiles:

```bash
curl http://127.0.0.1:8000/profiles
```

### Step C: Add sample audio for cloning (required for cloned voices)

`reference_text` should match the spoken content in the uploaded file.

```bash
curl -X POST "http://127.0.0.1:8000/profiles/<PROFILE_ID>/samples" \
  -F "file=@sample.wav" \
  -F "reference_text=Hello this is my voice sample."
```

### Step D: Request generation

```bash
curl -X POST http://127.0.0.1:8000/generate \
  -H "Content-Type: application/json" \
  -d '{
    "profile_id": "<PROFILE_ID>",
    "text": "This recording is generated by Voicebox API.",
    "language": "en",
    "engine": "qwen",
    "model_size": "1.7B",
    "normalize": true
  }'
```

Response includes `id` (generation id) and `status` (typically starts as `generating`).

### Step E: Poll status until completed

```bash
curl http://127.0.0.1:8000/history/<GENERATION_ID>
```

Wait until:

- `status = "completed"` -> audio is ready
- `status = "failed"` -> inspect `error`

Alternative real-time endpoint (SSE):

- `GET /generate/{generation_id}/status`

### Step F: Download the voice recording

```bash
curl -L "http://127.0.0.1:8000/audio/<GENERATION_ID>" --output output.wav
```

You now have a WAV file for playback, messaging, upload, or further processing.

## 4) Fastest Path for Other Project

If you just want text-in and audio-out with minimum calls:

1. Pre-create one profile and keep its `profile_id`
2. Your project calls `POST /generate`
3. Poll `GET /history/{generation_id}` until completed
4. Download from `GET /audio/{generation_id}`

## 5) Request/Response Fields (Most Important)

## `POST /generate` request body

- `profile_id` (string, required)
- `text` (string, required, max 50000 chars)
- `language` (default `en`)
- `seed` (optional int)
- `model_size` (`1.7B`, `0.6B`, `1B`, `3B`)
- `instruct` (optional)
- `engine` (`qwen`, `qwen_custom_voice`, `luxtts`, `chatterbox`, `chatterbox_turbo`, `tada`, `kokoro`)
- `max_chunk_chars` (default 800)
- `crossfade_ms` (default 50)
- `normalize` (default true)
- `effects_chain` (optional)

## Generation status values

- `loading_model`
- `generating`
- `completed`
- `failed`

## `GET /history/{generation_id}` important response fields

- `id`
- `profile_id`
- `text`
- `status`
- `error`
- `duration`
- `audio_path`
- `created_at`

## 7) Example: Python Client (Other Project -> Voicebox)

```python
import time
import requests

BASE = "http://127.0.0.1:8000"
PROFILE_ID = "replace-with-profile-id"

payload = {
    "profile_id": PROFILE_ID,
    "text": "Hello from my second project.",
    "language": "en",
    "engine": "qwen",
    "model_size": "1.7B",
    "normalize": True,
}

gen = requests.post(f"{BASE}/generate", json=payload, timeout=60).json()
generation_id = gen["id"]

while True:
    status = requests.get(f"{BASE}/history/{generation_id}", timeout=30).json()
    if status["status"] == "completed":
        break
    if status["status"] == "failed":
        raise RuntimeError(status.get("error", "Generation failed"))
    time.sleep(1.5)

audio = requests.get(f"{BASE}/audio/{generation_id}", timeout=120)
audio.raise_for_status()
with open("voice_output.wav", "wb") as f:
    f.write(audio.content)

print("Saved voice_output.wav")
```

## 8) Integration Notes and Best Practices

- Keep Voicebox backend running as a separate service process.
- Reuse existing profiles; avoid creating a new profile per request.
- For cloned voices, ensure sample audio and `reference_text` quality are good.
- Use async flow (`/generate` + status polling) for reliability.
- Handle `404`, `400`, and `422` responses cleanly in your app.
- First model load/download can be slower.

## 9) Troubleshooting

- `Profile not found` -> wrong `profile_id`
- `Generation failed` -> inspect `error` from `/history/{generation_id}`
- `Audio file not found` -> generation not completed or storage issue
- Server unreachable -> backend not running or wrong host/port
- Validation errors (`422`) -> request body has missing/invalid fields
